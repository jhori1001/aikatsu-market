## 2026-11-11（899,999円が相場に混ざった件）

### 相場の平均を出す前に、日輪と同じ外れ値の除き方を通すようにした

何を: 日輪の `services/pricing.py`（中央値の6倍超・6分の1未満を先に落とす → IQR法 → 中央値の0.5〜2倍のガード）を
そのまま持ってきて、`track_prices.asking_average()` で平均の前に通す（`rejudge_listings` の再計算も同じ関数）。
日輪の除き方は4件未満では何もしないので、アイカツは3件のときだけ「中央値の6倍超・6分の1未満」を落とす
（落ちて3件未満になれば平均は出さない）。

なぜ: ユーザー指摘「バグってる 金額おかしい」。オーロラキスドレープスカート（パラレル、E1-02_PR_p1）の 11/11 の平均が
70,740円（前日 11,280円）。inspect で調べると「アイカツカード オーロラキスドレープスカート 星宮いちご アンコール パラレル PR」が
**899,999円**で採用されていた（判定の言葉は全部そろっているので、仕分けでは落とせない値付け）。これまでの平均は外れ値を一切除いていなかった。

どうなった: 手元で再現すると 15件（899,999円を含む）→ 13件・9,950円。[10,000, 11,000, 899,999] の3件は平均なし（前は 307,000円）。
同じ調べで、ふつうのPRにも 15,999円（学生証付き）や 300〜750円（アクリルチャーム等のグッズ）が採用されていて、これらも中央値の0.5〜2倍の外として除かれる。

DBにしたこと: E1-02_PR だけ相場の記録を流し直し、11/11 の平均を付け直した。E1-02_PR_p1 は **70,740円 → 11,070円（16件）**、通常版の E1-02_PR も 3,380円 → 2,580円（15,000円・13,000円などが外れた）。ほかのカードは次の毎日の更新から新しい除き方になる。過去の日の平均は変えていない。

## 2026-11-11（売却済み・掲載終了／ページの作り直し）

### 検索に出なくなった出品を商品ページで確かめ、売却済み・掲載終了にするようにした（日輪と同じ）

何を: `backend/app/jobs/resolve_listings.py` を追加し、`track-prices` の相場の記録のあとに流す。最後に検索で見えてから6時間以上たった
「販売中」の採用出品を、商品ページ（/item/<id>、robots.txt で許可）で1件ずつ開き、売り切れなら sold（売れた日時＝商品ページの更新日時）、
ページが無ければ withdrawn（掲載終了）にする。1回200件まで（約13分）。マイグレーション 0004 で `sold_at`・`resolved_at` を追加。
出品一覧の「取消」を「掲載終了」にし、絞り込みにも足した。相場（販売中の平均）の出し方は変えていない。

なぜ: ユーザー指摘「売り切れのやつと、掲載終了したやつが販売中になってる 日輪と同じにして」。これまで一度記録した出品はずっと「販売中」のままだった。

DBにしたこと: 数えるだけ（先頭20件: 売却済み14・掲載終了6）を確かめてから本番を1回。採用出品のうち検索に出なくなった
1,323件のうち200件を確かめ、**売却済み 121件・掲載終了 75件**に変えた（まだ販売中 1件、状態 HOLD〈取引中〉3件は販売中のまま）。
残り約1,120件は毎日の自動実行で200件ずつ片付く（約6日）。

### 毎日の更新のあとの「サイトのページを作り直す」が、毎回飛ばされていたのを直した

何を: 5個のワークフローの条件を `inputs.apply != false` → `format('{0}', inputs.apply) != 'false'` に。
なぜ: `apply` の入力が無い実行（毎日の自動実行など）では `inputs.apply` が null になり、GitHub の式では null と false が等しいと
見なされて、作り直しが毎回 skipped になっていた（11/10 の自動実行でも skipped）。相場の更新が、push したとき（Vercel のビルド）にしか
画面に出ていなかった。日輪も同じだったので同時に直した。
